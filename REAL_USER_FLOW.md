# MURA — Real User Flow & Operational Runbook (Phase 1.6)

## 1. Product Mission & Mental Model

> **«Я просто разговариваю с бабушкой.»**

MURA (Мұра — «наследие») — это семейный голосовой архив, созданный для сохранения устной истории семей Казахстана и Центральной Азии. Продукт устраняет барьеры между поколениями, превращая живую устную речь в структурированную летопись, генеалогическое древо и архив воспоминаний.

### Принципы пользовательского взаимодействия
1. **Теплота и простота**: Интерфейс исключает технический жаргон (нет «LLM», «ASR», «embeddings», «pipeline jobs»). Пользователь видит только понятные понятия: *Запись*, *История*, *Человек*, *Семья*, *Древо*.
2. **Правдивость состояний**: Никаких фальшивых индикаторов прогресса (например, искусственных процентов 0–100%). Если файл транскрибируется — показывается реальный статус.
3. **Evidence Grounding (Опора на первоисточник)**: Каждое утверждение и факт в архиве подтверждаются подлинными словами рассказчика (verbatim evidence spans).
4. **Надёжность и отказоустойчивость**: Любая аудиозапись сохраняется локально и на сервере; пользователь может закрыть вкладку в любой момент — обработка завершится в фоне.

## 2. Пошаговый путь пользователя (End-to-End User Flow)

### Шаг 1: Первое знакомство (Landing & Onboarding)
- **URL**: `/` (перенаправление на `/onboarding` для новых гостей).
- **Экран**:
  - Фирменный логотип MURA / Мұра с мотивом переплетённых кругов поколений.
  - Понятный заголовок: *«Отбасыңыздың дауысы. Мәңгілікке.» / «Голос вашей семьи. Навсегда.»*
  - 3 ключевых шага: Запись разговора → Анализ и выделение фактов → Семейный архив.
  - Четкие кнопки действий:
    - Неавторизованный пользователь: **«Создать архив»** (`/sign-up`) и **«Войти»** (`/sign-in`).
    - Авторизованный пользователь: Кнопка **«Перейти в архив»** (`/home`).

### Шаг 2: Аутентификация и создание архива
- **Провайдеры**: Dev Auth (локально / staging) или Supabase Auth / Clerk (production).
- При первом входе пользователь задаёт имя своего семейного архива (например, *«Семья Ахметовых»*).
- Сессия изолирована: все запросы проверяются на уровне сессии и базы данных PostgreSQL.

### Шаг 3: Главная страница и сценарий первого запуска (First-Run)
- **URL**: `/home`
- **Состояние пустого архива**:
  - Вместо пустой серой страницы отображается приветственный экран с маскотом (Ласточка) и карточкой первого старта.
  - Яркая главная кнопка: **«Записать первую историю»** (`firstRunCta`).
  - 4 стартовых вопроса-подсказки (адаптируются в зависимости от роли: родитель, ребёнок, внук), например:
    - *«Расскажите о самом ярком событии вашего детства»*
    - *«Как ваши родители познакомились?»*
    - *«Какие семейные традиции передаются из поколения в поколение?»*

### Шаг 4: Запись и загрузка аудио (`/record`)
- **Режимы сбора**:
  1. **Микрофон («Записать сейчас»)**: Прямая запись с браузера с визуализацией громкости (Waveform) и превью распознавания речи в реальном времени.
  2. **Файл («Загрузить файл»)**: Возможность загрузить ранее записанный разговор (диктофонные записи WhatsApp, диктофонные заметки iPhone/Android).
- **Форматы и ограничения**:
  - Поддерживаются: MP3, M4A, WAV, WebM, OGG, AAC.
  - Лимит размера: до 25 МБ (`core_max_upload_mb = 25`). Проверка выполняется мгновенно на стороне браузера и повторно валидируется сервером.
- **Обязательная атрибуция рассказчика (Speaker)**:
  - Перед сохранением обязательно указывается, кто говорит (выбор из существующих членов семьи либо ввод нового имени).
  - Это предотвращает появление безымянных записей в архиве.
- **Язык аудио**:
  - Выбор языка рассказчика (Казахский, Русский, Английский). Независим от языка интерфейса!

### Шаг 5: Фоновая обработка (`/processing`)
- После нажатия «Отправить» аудиофайл загружается в объектное хранилище (Supabase Storage / Local S3), а задача помещается в очередь PostgreSQL (`SKIP LOCKED`).
- Экран обработки информирует пользователя о честных этапах:
  - *Загрузка записи*
  - *Очередь на обработку*
  - *Распознавание речи (GigaAM / Whisper)*
  - *Анализ фактов, дат и родственников*
- Пользователю явно сообщается: *«Вы можете закрыть это окно — запись сохранится в архиве автоматически»*.

### Шаг 6: Просмотр воспоминания и доказательства (`/story/[id]`, `/memory/[id]`)
- **Воспроизведение аудио**:
  - Плеер с перемоткой. Если локальный кэш IndexedDB недоступен (например, открыто на другом устройстве), плеер автоматически подгружает аудио с сервера (`/v1/families/{id}/recordings/{id}/audio`).
- **Связность данных**:
  - **Краткое содержание**: Связный пересказ воспоминания.
  - **Упомянутые люди**: Карточки с именами и родственными связями с прямой ссылкой на профиль в древе.
  - **События и места**: Хронологические маркеры.
  - **«Свидетельства из рассказа» (Evidence Grounding)**: Блок с цитатами — дословные фрагменты из речи рассказчика, подтверждающие каждый выделенный факт.
  - **Полный текст**: Чистый читаемый транскрипт.

### Шаг 7: Семейное древо (`/tree`)
- Все извлечённые родственники и связи автоматически отображаются в интерактивном графе семьи.
- Новые члены семьи отмечаются значком новизны, пока пользователь не подтвердит их положение в древе.

## 3. Обработка краевых ситуаций и ошибок

| Сценарий | Поведение системы | Сообщение для пользователя |
| :--- | :--- | :--- |
| **Микрофон заблокирован** | Кнопка записи деактивируется, выводится предупреждение | *«Разрешите доступ к микрофону в настройках браузера»* |
| **Файл > 25 МБ** | Клиентский валидатор отклоняет файл до загрузки | *«Файл слишком большой. Максимальный размер — 25 МБ.»* |
| **Неверный формат файла** | Отклонение текстовых/видео/бинарных файлов | *«Этот формат не поддерживается. Выберите MP3, M4A, WAV, WebM или OGG.»* |
| **Не указан рассказчик** | Кнопка отправки недоступна; ссылка-подсказка скроллит к полю выбора | *«Укажите, кто рассказывает эту историю»* |
| **Сбой сети при загрузке** | Запись остаётся в локальном хранилище IndexedDB | *«Не удалось отправить запись. Проверьте интернет и повторите.»* |
| **Временная недоступность воркера** | Задача остаётся в очереди PostgreSQL с возрастающим backoff | Статус «В очереди» с возможностью вернуться позже |

## 4. Эксплуатационный регламент (Operational Runbook)

### 4.1 Проверка состояния сервисов
```bash
# 1. API Health Check
curl http://localhost:8000/health

# 2. Worker & Queue Health (Operator-only)
curl -H "Authorization: Bearer $OPERATOR_TOKEN" http://localhost:8000/v1/operations/queue-health

# 3. AI Provider Usage & Costs
curl -H "Authorization: Bearer $OPERATOR_TOKEN" http://localhost:8000/v1/operations/ai-usage
```

### 4.2 Диагностика логов и трассировка
Все логи пишутся в structured JSON формате. Для расследования проблемы пользователя используйте корреляционные идентификаторы:
- `request_id`: Трассировка HTTP-запроса от Next.js до FastAPI.
- `job_id`: Идентификатор задачи обработки в PostgreSQL очереди.
- `recording_id`: Идентификатор аудиозаписи и её файлов в хранилище.

Пример поиска в логах Railway / Grafana:
```json
{ "recording_id": "rec_01J..." }
```

### 4.3 Приватность и безопасность
- **Transcripts & Audio**: Никогда не логируются в stdout и не передаются в Sentry.
- **Tokens & Secrets**: Заголовки `Authorization` и cookies маскируются (`[REDACTED]`).
- **Операторские эндпоинты**: `/v1/operations/*` запрещены в Next.js proxy allowlist и требуют отдельный `OPERATOR_TOKEN`.
